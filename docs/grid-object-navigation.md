# 空间对象查阅与跨页联动

本文说明节点紧凑表格、统一对象详情和空间页面间的关联导航。披露趋势、主题、时段选择与信息分组另见 [公开披露交易信息台](disclosure-trading-desk.md)。

## 节点页先查阅，详情中维护

`/grid-assets/nodes` 默认显示按站收拢的紧凑表格，每站一行，显示所属站、匹配节点数、电压概览、地区、位置状态计数和价格引用数量。点击站名展开该站匹配节点，再点击节点名称打开统一详情；资产维护、版本历史和内部字段保留在详情维护区。

顶部“匹配节点、已定位、近似位置、未定位”是**完整筛选范围**的统计。搜索、节点类型、位置状态以及跨页对象关联共同决定范围。表格标题与分页栏中的“本页”只表示当前页，不能拿当前页条数推算全部节点或位置状态数量。服务端未提供完整统计，或各项之和与匹配总数不一致时，对应统计显示“未提供”。未定位只表示位置资料不足，不表示停运。

站级汇总按完整筛选结果生成，默认每页 20 个站组，同一站不会因原节点分页被拆开。首次展开才读取该站的节点明细，按“电压等级 → 母线／节点”整理；每个节点独立显示完整六列，所属站和电压逐行重复展示，不合并单元格。每次最多 60 条，超过时通过“加载更多节点”继续查看，明确显示已读取数和本站匹配总数。收起再展开复用当前筛选下已读取的明细；搜索、地区、公司或对象上下文改变后清除失效明细，旧响应不能覆盖新内容。不同电网或地区的同名站分开，站名无法确认的节点各自独立保留。

“同站节点合并”可取消，仍支持平铺紧凑表格与资产卡片。切换分页单位时回到第 1 页：站级视图按站分页，平铺／卡片按节点分页。顶部仍统计所有匹配节点；底部分别显示站组总数、本页站组数及其匹配节点数，不能混用站数与节点数。搜索后展开只显示当前条件匹配的节点。

接口复用 `GET /api/v1/grid/geo-assets/nodes`：`groupBy=station` 返回 `data.groups`、完整匹配节点数 `data.totalNodes`、节点 `summary` 与按站计算的 `pagination`；明细使用原节点列表格式，传入不透明的 `stationGroupKey` 和相同筛选条件。无分组参数的既有接口语义保持不变。

- 所属站由节点名称结构或接口明确返回的名称解析结果呈现，并标注“名称解析”。无法确认所属站的节点独立保留，不把它们并为同一个未知站。
- 节点电压优先使用已登记值，其次使用节点名称中**节点段**的明确电压。只有站名前缀电压时，节点仍显示“待补录”，另提示站级电压。
- 例如 `220kV三都站.110kV#1母` 的站名含 220 kV，节点段为 110 kV；不会用站级 220 kV 覆盖节点段。
- 分组和名称解析仅用于阅读，不会自动写资产字段、建立母线连接或证明电气拓扑。编辑页的解析建议仍须显式采用后提交。
- “节点价格引用”表示登记了数据引用，不承诺所选日期有该节点价格。没有时序覆盖时显示缺数。

## 统一详情与阅读流程

节点、场站和披露对象使用同一详情抽屉，包含“位置与关联”“出力与时序”“关注与笔记”三个页签。

详情采用紧凑阅读布局：顶部并排展示对象身份与业务日期，关联页面集中在一条工具栏，页签用下划线区分。基础属性、来源时间、位置可信度和天气口径使用横向“字段／值”，缺测和无关联采用状态标签，不在概览铺开说明段落。较长的原始来源、位置与许可说明默认折叠，展开后按原文分条展示；原有来源链接继续可访问。维护资料保持折叠。窄屏日期自动换行、字段改为单列，完整名称允许换行。

1. 从节点名称、场站完整信息或选中披露的对象入口打开详情。
2. 在“位置与关联”查看对象名称、已提供的位置和属性、确认的场站/节点关联与来源。点击已确认关联可继续在抽屉内查看；“返回上一个对象”回到上层对象。
3. 选择业务日期，通过“位置、相关节点、出力、气象、相关披露”进入对应空间页。日期与合法选区随导航传递；更改日期后不再携带上一日期的时段。
4. 在目标页顶部查看当前对象、地区和日期。无确认关联的功能保持不可用或说明空态，不自动选取其他厂站或通道。
5. 使用“返回来源”回到原空间页，或者显式“清除关联”后查阅当前公司、地区的完整目录。

空间驾驶舱中，按 Esc 优先关闭当前详情或维护弹窗，保留底层选中对象；回到地图后再次按 Esc 才清除选择。同一次弹窗按键不会继续触发地图清除。

基础详情不预填无来源的容量、电压、坐标、发布时间。来源更新时间明确区分“资产更新”与“源记录入库”；入库时间不替代披露发布时刻或设备生效区间。只展示实际提供的公开来源链接。

场站详情包装保留原有资产版本、人工覆盖、维护入口、详细位置证据与当前天气格点说明。抽屉跳转到另一个关联对象后，原对象的维护区与额外天气/坐标资料不附在新对象下面。

## 五个对象接收页面及空间边界

| 路径 | 当前页面行为 |
| --- | --- |
| `/grid-assets/command` | 接收场站或节点对象并选择、定位目标。节点即使不在地图首批分页中，也可使用已授权详情中的有效 WGS84 坐标定位；缺坐标的对象仍可查详情，不生成坐标。披露对象有已确认关联场站时可定位该场站。 |
| `/grid-assets/nodes` | 服务端按当前对象筛选关联节点；搜索、类型、位置状态与分页仍可继续使用，无关联时不打开全目录。 |
| `/grid-assets/disclosures` | 对象筛选同步作用于全日期事件轨道、选区统计、分组、组内明细和逐条列表。价格及供需曲线保留标明的地区口径；存在明确指标/通道绑定时锁定对应对象，底层自动返回其他通道也不展示为本对象曲线。 |
| `/grid-assets/market` | 带对象进入时，仅向市场快照传入已确认关联、且属于当前授权范围的场站；日期取传入业务日期。没有关联场站时保持空态。 |
| `/grid-assets/weather-impact` | 带对象进入时选择已确认关联场站，使用传入日期；有合法选区时以北京时间定位起始小时。没有关联场站时不默认加载首个电厂。 |

`/grid-assets/topology` 保留既有网架 Provider、授权资料、公开证据和权限边界，列入安全返回路径，但本轮没有接通对象定位或拓扑关联。节点表格分组与名称解析不构成电气连接证据。

跨页对象关联只确认对象之间的身份关系，不提高原数据的空间精度，也不扩大可读取公司或地区的范围。旧节点电价、结算等业务入口可以携带公共查询信息，但本轮不声称这些非空间页面已自动定位同一对象。

## 场站、机组与记录的身份

阅读分组、对象关联和单条披露是不同层次。披露列表可以把同厂多台机组归为一组便于阅读，但不会因此把每台机组的对象笔记、停复电区间或事件身份合并。

同厂 `#1` 与 `#2` 机组必须保持独立；只有来源能确认同一厂内同一机组时，跨日期记录才可以共用该机组的对象笔记与关注。整厂对象才做厂级聚合。缺少厂名依据的 `#1`、`#2F` 或设备编号，不凭名称相似合并到某个电厂，也不从一次列表归组结果推导稳定对象身份。

前端仍以服务端返回的对象引用导航，不根据标题自行构造机组身份。披露入口保持 `kind=disclosure` 与稳定源 `eventId`，未新增前端机组 ID。详情 `name` 保留完整原始对象名；能明确识别机组时 `objectType` 为“机组”，`stationName` 表示来源明确的上级场站。

后端按发布方（南网整年导出与 2026-07-03 起日文件接续同属南网，dljy#3517）、地区、完整 `objectName` 与明确 `plantName` 精确关联具体对象；同一机组的跨日对象笔记共享，原有单事件笔记完全独立。同厂不同机组、不同厂同名 `#1F` 不合并，纯编号且无明确厂名的记录继续按事件隔离。只有 `objectName === plantName` 的明确整厂源记录，或已授权场站资产入口，才使用全厂范围。父级 `groupKey` 只表示列表阅读归组，不扩大单机组对象的筛选范围。

机组关联到所属场站后，所展示的场站装机、场站出力和天气格点仍为**场站口径**。不能把整厂容量、整厂出力或区域气象写成该机组独立容量、独立计量或现场传感器实测。没有机组独立数据时明确缺少该口径。

## 公司、地区、日期与返回

导航使用统一查询字段，所有接收页校验对象地区和公司与当前已选范围一致。无效、越范围或无法解析的对象保持关联不可用状态；用户明确清除关联之后，才允许回到完整目录。页面不因当前对象缺数自动换公司、地区、日期或选择无关对象。

同组件内切换 A、B 对象会使 A 的在途请求失效，并清除不再适用的曲线、列表与详情。请求失败与无权限均不作为“可展示上一对象”的理由。空值保持缺测，真实零值继续有效。

空间页面通过 KeepAlive 保留本次会话的阅读状态。离开页面时保留各自对象查询；返回**相同对象输入**时不重新应用最初日期去覆盖用户现场修改的日期、搜索或筛选。只有新的对象输入才重新应用其上下文。页面滚动位置按公司、地区和完整路由分别恢复，缓存有界；这是会话内页面状态保留，不承诺浏览器刷新或重新登录后恢复。

页面的关联栏与详情跳转优先使用当前页面业务日期，而不是过期的 URL 初始日期。合法选区带显式时区且起点不晚于终点；只有日期、非法日期或倒置时段不能构成有效选区。显示时间采用北京时间。

空间驾驶舱、市场与气象页在没有对象上下文时，初始业务日期取打开页面时的北京时间当天，不使用固定历史回放日。对象跳转携带明确历史日期时仍沿用该日期，披露页标识“数据回看”；“今天”按钮可回到当前北京时间日期。缺少当天数据不自动切换到历史日。

## 关注、笔记与权限

“关注与笔记”区分个人与公司范围。个人关注、笔记和标签与公司共享笔记分开读取、保存。公司写入能力取当前权限清单；没有修改权限时保留允许的查阅，禁用公司笔记和资产维护写操作，后端仍执行授权校验。

保存提交 `expectedVersion`，首次保存使用当前不存在版本的初始值。遇到 HTTP 409 不自动覆盖：保留正在编辑的草稿，读取并显示最新版本，再由用户选择采用最新内容或核对后保留草稿继续保存。最新版本读取失败时保留草稿并提供重试，不能绕过版本核对。切换对象、笔记范围、公司或地区使旧保存/重读响应失效。

界面限制笔记最多 2000 字、最多 10 个标签、每个标签最多 40 字。标签按中英文逗号拆分、去重。笔记不影响源记录、对象位置或电气连接关系。

## 前后端契约

以下 URL 使用默认 `/api` 前缀；前端通过 `src/features/gridGeo/client.ts` 和统一 API 客户端取数。实际请求携带当前公司及统一鉴权/地区上下文，URL 的对象参数不能代替授权。

| 接口 | 主要字段和约束 |
| --- | --- |
| `GET /api/v1/grid/geo-assets/nodes` | `page`、`pageSize`、`keyword`、`nodeKind`、`locationStatus`；关联查询增加成对的 `objectKind`、`objectId`。返回 `data.items`、完整查询 `data.summary`、可选 `data.pageSummary`、`data.pagination` 与可用性。前端顶部仅采信自洽的完整统计，当前页来自 `items`。 |
| `GET /api/v1/grid/geo-assets/objects/{kind}/{id}` | `kind` 为 `plant`、`node`、`disclosure`；ID 为不透明身份，路径需编码。返回 `data: GridObjectDetail`。前端核验返回的种类、ID 和地区均与请求一致。 |
| `PUT /api/v1/grid/geo-assets/objects/{kind}/{id}/overlay` | 正文为 `scope: user/company`、`favorite`、`note`、`tags`、`expectedVersion`；成功返回 `data.overlay`，版本冲突返回 409。对象层笔记与单事件标注接口用途不同，不混用身份。 |
| `GET /api/v1/grid/geo-assets/disclosures/overview` | 统计完整筛选范围；支持与关联披露同一 `objectKind/objectId`。全日期轨道保留对象和顶部搜索；选区统计另按所选窗口与专业条件查询。 |
| `GET /api/v1/grid/geo-assets/disclosures/groups` | 对完整查询范围归组、分页；对象参数与明细保持一致，组计数不由当前页明细推算。 |
| `GET /api/v1/grid/geo-assets/disclosures/events` | 明细列表继承对象参数及日期、类别、搜索、重叠时间等条件。组内读取另外带服务端返回的不透明 `groupKey`。 |

`GridObjectDetail` 的主要字段：

- `reference: { kind, id, regionId, gridOperator? }`：导航入口引用。
- `name`、`objectType`、`capacityMw`、`voltageLevelKv`、`stationName`、`location`：对象事实及位置状态；缺值保留 `null`。
- `relations.plants/nodes: [{ id, name, regionId }]`：后端确认的关联对象，不是前端名称搜索候选。
- `disclosureFilter: { objectKind, objectId }`：关联披露身份契约。
- `metricRefs?: [{ metricId, channel }]`：可选精确指标绑定。指定断面缺数时不接受自动选择其他断面的结果。
- `overlays`：个人/公司标注及其版本；`source`：来源标签、已提供的链接和更新时间依据。`updatedAtBasis` 区分 `asset-updated` 与 `source-imported`。
- `plant?`、`node?`：已授权原资产详情，供场站业务时序、位置或维护使用。

公共导航由 `buildGridObjectLocation(path, reference, context)` 构造：

| 查询字段 | 含义 |
| --- | --- |
| `objectKind` / `objectId` | 对象种类与不透明 ID；不得根据短名、序号或当前页索引生成。 |
| `objectRegion` / `objectCompany` | 来源对象的地区与当前公司，接收端必须与当前范围一致。 |
| `objectDate` | 有效日历日期 `YYYY-MM-DD`；页面可继续改日。 |
| `objectFrom` / `objectTo` | 可选带时区的 ISO 起止时刻，必须同时有效且顺序正确。 |
| `returnTo` | 可选内部来源路由；仅接受五个对象接收页面和 `/grid-assets/topology` 的内部路径，拒绝外部地址和非法路径。 |

`useGridObjectContext()` 暴露 `reference/detail/date/timeWindow/error/loading/hasContext/active`。`hasContext` 区分“未带关联”和“带了无效关联”；`active` 区分当前显示页与 KeepAlive 中的隐藏页。消费方不能把 `reference === null` 一律解释为解除筛选。页面本地日期变化后，应向 `GridObjectContextBar` 和 `GridObjectDrawer` 传入当前 `date`，并避免携带旧日期选区。

## 验证入口

产品验证应覆盖：节点超过一页时的完整统计、名称解析与电压冲突、无坐标对象、对象 A/B 快速切换、无关联和越公司上下文、明确断面缺数、真实零值、同对象返回保留日期/搜索、同机组跨日笔记与不同机组隔离、409 后草稿保留和重读失败，以及窄屏与键盘访问。

前端专项包括 `nodeTable.spec.ts`、`GridGeoNodeTable.component.spec.ts`、`GridGeoStationTable.component.spec.ts`、`GridGeoNodeManagerView.component.spec.ts`、`objectNavigation.spec.ts`、`GridObjectDrawer.component.spec.ts`、`gridObjectPlantPages.component.spec.ts` 和 `GridDisclosureObjectContext.component.spec.ts`。本轮集成验收中，前端 lint、类型检查、单测、覆盖率与构建五类检查通过（单测和覆盖率采用下述默认 bundle loader 命令）；219 个测试文件、2530 项测试通过。覆盖率为语句 56.62%、行 57.79%、分支 51.52%、函数 51.30%。站级展开专项还覆盖单站 125 个节点分批读取、第二页失败重试、重复页、无站名对象和旧响应隔离；后端专项覆盖 66 个同站节点、完整分组翻页与权限隔离。最新独立行展示检查日志位于 `output/independent-rows-*.log`。

### 测试执行说明

本地完整单测与覆盖率使用 Vitest 默认 bundle loader，进程内固定地形提供方：

```powershell
$env:VITE_GRID_GEO_TERRAIN_PROVIDER = 'arcgis-terrain'
node node_modules/vitest/vitest.mjs run
node node_modules/vitest/vitest.mjs run --coverage
```

现有 `npm` 测试脚本指定的 runner loader 在本环境报 `picomatch: require is not defined`，因此本轮完整门禁使用上述等效入口。现有 `.env.local` 的地形配置会影响依赖默认值的测试，故只在测试进程设置该环境变量；没有改动应用配置、依赖或本地配置文件。

### 真实浏览器验收
