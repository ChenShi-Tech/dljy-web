# 云南市场洞察跨省与电网边界页（dljy#3024）

云南地区工作区 `/insight/grid-boundaries` 页（`YunnanGridBoundariesPage.vue`）的使用与口径说明。契约定义在后端仓（`dljy/shared/insight/`，经 `npm run sync:web` 镜像到本仓 `shared/insight/`，只读），本文只讲前端消费方式与守住的口径红线。

> 相关文档：[市场洞察数据口径说明](./market-insight.md)、[市场洞察公共证据组件与图表选区](./market-insight-common-components.md)、[云南市场洞察供需与水电页](./market-insight-supply.md)。

## 交付边界

- **本页（任务 10.5）**：三页签——送受电（公开背景曲线 + 获权逐日送电）、通道断面（获权曲线 + 限值配对）、备用机组（获权容量序列 + 记录清单）。
- 页面已 `delivered: true` 进导航（`workspace.ts`）；plants / research 仍为占位，不受本页影响。

## 分析目录

页顶固定一句口径：**方向与符号**（送受电与通道潮流的正负号是方向：负值是反方向，原样保留、不取绝对值）。

| 分析 | analysisId | 视图/入参 | 授权 |
| --- | --- | --- | --- |
| 跨省送受电（公开披露） | `grid.boundary-series` | `view: series`（31 天上限），无对象维度 | 公开 |
| 逐日送电与通道能力 | `grid.transfer-daily` | `view: series`（31 天上限），无对象维度 | 获权 |
| 省间联络线与断面限值 | `grid.channel-flows` | `view: series / limit-match`（**7 天上限**），`objectIds` 必选（≤30） | 获权 |
| 备用、检修容量与机组群 | `grid.reserve-units` | `view: series`（31 天上限），`objectIds` 必选（≤50） | 获权 |
| 是否调峰与必开必停清单 | `grid.unit-lists` | `view: records`（31 天上限），`objectIds` 必选（≤50） | 获权 |

- 获权可见性按能力目录判定：公共账号不渲染获权区块、不发获权查询与覆盖请求，所在页签显示一条「获权数据需开通」；**不显示空框**。

## 三页签口径

每个页签懒加载（首次激活才查询），口径不变时切走再切回**不重查**。

### 送受电

- **跨省送受电（公开披露）**：公开分析背景曲线（省间送受电预测、稳定断面负载率、正/负备用预测等公开来源），无对象维度、进页即查。
- **逐日送电电量与通道能力（获权）**：逐日送电电量下限（MWh）、通道最大可用能力（MW）、断面负载率（%）分列；曲线 + 明细表。**方向与符号原样保留**：送出为正、受入/回落为负，不取绝对值、不因负值截断。

### 通道断面

- **对象选项来自覆盖接口（coverage）**：页面对该分析发 `fetchInsightCoverage`（filters 不带 objectIds），取各来源 `objects` 的**并集**做选择器选项（上限 30）。三种清单状态都必须诚实：
  - sources 里没有任何 `objects` 字段（运行实例未部署新后端）→ 显示「对象清单需要新版洞察服务，当前无法列出」，选择器禁用、**不发查询、绝不伪造选项**；
  - `objects` 为空数组 → 「所选窗口内没有可选对象」，同样不发查询；
  - `objectsNote`（如清单超 200 截断）原文透出。
- **通道潮流（series 视图）**：15 分钟潮流曲线，正负号是方向。
- **限值配对与裕度（limit-match 视图）**：后端 `gridLimitMatch` 只在**同名通道、同方向、同一时段**（且业务范围、量纲、粒度一致）配对；配对上的时段给出实际、正向/反向限值、裕度（上界裕度与下界裕度中较小者，**负值表示超出限值区间**，原样显示）、约束侧与负载率。按通道统计卡：配对时长、超出限值区间时长、缺限值/限值区间不成立时长、最小裕度、最高负载率（指标名取共享登记）。
  - **无配对时逐条展示后端原因**（没有同名限值、只有单侧限值、名称近似不自动匹配等），不渲染配对表、不显示虚假的输电裕度；
  - 固定说明：这是实测与披露限值的对比，**不是可用输电能力**，也不等于调度认定的越限；后端 notes 原文透出。
- **7 天窗口上限**：业务日期窗超过通道断面上限（7 天）时页面拦截查询并提示缩窗；窗口合法后自动恢复。

### 备用机组

- **备用与检修容量（获权）**：高峰备用容量实际、正负备用预测、检修容量、机组群占比等序列（曲线 + 明细表）；容量是容量、占比是占比，按原义分列、不换算出力。
- **是否开展调峰与必开必停清单（获权）**：`records` 记录视图。**记录不是时序曲线**：按业务日列表呈现（业务日、清单、区域/电厂/机组/必开必停等维度列、内容），不画曲线、不换算出力；维度列按行动态生成、列名映射业务语言。

## coverage objects 消费方式（页面对象选择器的数据前提）

- 后端（dljy 主仓 `runCoverage`）在 coverage 响应的 `sources[]` 里，对有对象维度的来源附带 `objects: string[]`（窗口内出现过的对象，按名称排序、超 200 截断）与可选 `objectsNote`。
- 前端类型（`insightClient.ts` 的 `InsightCoverageSource`）把两个字段声明为**可选**：字段缺失 ≠ 空数组——前者是「老后端无法列出」，后者是「窗口内确实没有对象」，页面据此分别给「无法列出」与「没有对象」两种说明。
- 覆盖请求与查询一样走上下文代次：窗口/地区/公司变化后对象清单**作废重列**，已选对象保留（清空与否由地区/公司切换的全局规则决定）。
- 三个获权分析（通道断面、备用机组、机组清单）的清单**各自拉取、各自持有**，不跨分析混用选项。

## 页面状态纪律

- **前置拦截**：未选对象、对象清单不可用（老后端/为空）、通道窗口超 7 天、能力目录无获权分析——页面层直接不发请求（后端校验是第二道防线）。
- **口径签名**：查询键 = 查询名 + 上下文代次（日期窗/地区/公司）+ 各查询自身的对象选择；上下文变化清空全部查询结果与对象清单并重查，局部对象选择变化只作废对应分析的查询。
- **迟到作废**：所有查询（含覆盖清单）经 `ctx.request.run`（代次机制），旧口径的迟到响应不写进新状态；失败也记键，同一口径下不自动反复重试。
- **单区块失败隔离**：每个区块独立 error/retry（InsightBlock），一个区块失败不影响其他区块。
- **历史候选**：「查看可分析日期」按公开背景曲线分析的三条公开来源求交集（获权来源不参与候选），候选只经用户点击生效。
- 不缓存任何私有结果（获权数据零落盘），切地区或公司由上下文代次统一作废。
