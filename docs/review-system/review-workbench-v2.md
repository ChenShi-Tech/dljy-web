## 1. 产品目标与交付边界

交易员每天依次完成：发现要处理的异常 → 定位交易与时段 → 核实资料和金额 → 回到当时判断 → 留下具体改进 → 下一周期验证。后台计算、证据留存、前端导航必须围绕同一条业务链。

必须区分三件事：经营结果、相对事前基准的增益、在当时资料条件下的决策质量。缺少收入、合约或结算项目时，只显示具备条件的成本或收入分项，不能把现货购电费用称为利润。

此次交付是完整页面结构、代表性可操作流程、全功能落位表和建设契约；没有改动在用 Vue 页面，没有调用真实交易写入，没有接入正式账单。原型中的所有金额、公司和记录均为虚构；草稿只在当前页面内存保留，刷新清除。31 类模板均可搜索、分类和打开布局；代表性表单演示人工填写与提交锁定，不代表 31 套差异化表单已经完成。

## 2. 五个页面与一条上下文

继续使用 `/xhjy/review`，不新增并行复盘中心。

| 一级页面 | 交易员要回答的问题 | 主体布局 | 主操作 |
|---|---|---|---|
| 复盘总览 | 今天先处理什么？ | 三个摘要；左侧按影响与时限排序的事项及异常时段，右侧资料缺口与改进回查 | 打开第一项异常；准备晨会 |
| 交易分析 | 影响来自什么交易、什么时段？ | 二级标签：经营结果、电量偏差、市场环境、策略表现、风险检查；主图与联动明细 | 选时段查看证据、登记原因或改进 |
| 结算核对 | 账单与测算为何不同？ | 核对进度、逐项差异表、凭证与处理记录 | 导入预览、处理差异、满足条件后确认 |
| 决策回放 | 当时看到了什么，能做什么？ | 时间节点；已知资料与动作；人工判断 | 保存本人判断；显式切换事后结果 |
| 复盘档案 | 哪些结论已留存，改进是否有效？ | 待办与改进、报告与模板、案例与会议、学习记录 | 完成待办、复查改进、阅读或更正报告 |

公司来自全站授权上下文，不新增一套身份选择器。地区、业务主体、日期和周期在页头固定位置，进入详情后不改变。实际接入全站外壳时复用已有公司/地区切换，避免两处互相冲突；原型保留完整页头便于独立评审。

日度选择业务日，周度显示周起止，月度选择月份，季度显示自然季度范围。结算核对独立显示账期，不能把页头业务日偷偷当成账期。筛选项在桌面同一行；窄屏先换行，不隐藏公司、地区或资料状态。

保留既有深链 `date`、`declarationId`、`dim`、`todo`：六维旧链接映射到新位置；申报深链定位到具体业务单及修订，不跳转到一个无关联日期；无权或不存在则诚实提示。新增导航和时段参数只使用产品级标识，不在页面显示技术键。

## 3. 表征逻辑：由信息用途决定展示方式

| 信息 | 首层如何展示 | 点击后如何展开 | 不能采用的做法 |
|---|---|---|---|
| 结果金额 | 业务名称、数值、单位、测算/已核对状态 | 分项、资料名称、有效规则、计算时间和修订关系 | 一个“收益”数字混合收入、成本、利润 |
| 相对基准表现 | 增益正负及其经济意义；售电补“成本增加/减少” | 基准制定时间、适用范围、实际与基准逐项对照 | 负成本当作负利润；事后最优当作可实现收益 |
| 数据缺口 | “缺少出清回执，暂不能判断成交”，附处理入口 | 缺哪份资料、影响哪些功能、由谁补齐 | 只写横杠、英文枚举或伪造 0 |
| 风险事项 | 已发生损失与险情分别命名 | 发生事实、证据、影响、处置及案例 | 潜在损失混入已实现损失 |
| 异常时段 | 与金额同一来源的时段图，选中后表格联动 | 电量、电价、费用、申报/出清/执行链 | 只提供日级 Top5，却称为单笔交易 |
| 归因 | 已确认会计贡献、待核实解释、本人判断分区 | 每条证据、影响范围、确认人及时间 | 用相关性直接归责，AI 自动确定责任 |
| 改进 | 处理人、期限、当前阶段与下次回查时间 | 适用条件、比较基准、验证窗、成功/撤回条件 | 按“已执行”直接显示“已有效” |
| 报告 | 业务日期、范围、版本状态、待本人确认项 | 正文、数字来源、留存结论、更正记录 | 报告、图表和导出各算一套数 |

首屏只留“当前结果、相对基准、待处理事项”三组摘要，不为每个维度新增指标卡。金额和时间使用等宽数字；全部单位明确，金额精度遵从服务端口径，详情保留原始精度。红色表示不利影响/错误，绿色表示有利影响/已核对，始终附文字，不能只靠颜色。

96 点是当前适用示例的结算底座；不能把每个地区、品种、日期都写死为 96 点。小时视图只是展示聚合。电量按时间相加，电价按适用口径加权或保留分时值；不能用平均价重新算出另一套费用。表格提供原结算粒度导出。

## 4. 页面的具体交互与状态

### 4.1 总览：事项优先

默认按需处理程度排序：结算/执行异常优先，同类按经济影响、临近时限、重复发生与可信度排序。前端展示排序原因，不自行以金额推断交易员责任。不确定影响写“待量化”，不能排成 0 元普通事件。

一条事项仅保留标题、业务时间、影响、当前处理状态和一个主动作。次要动作以文字按钮呈现。点击后保持筛选、列表位置；宽屏显示同页详情，窄屏详情纵向展开。每次只展开一个详情；关联跳转替换详情并保留返回来源，不叠加抽屉。原型采用纵向详情以便完整查看，正式实现宽屏可采用右侧 420–480px 详情区。

首页资料区只显示会影响当前判断的缺口，完整列表折叠在“资料清单”。触发器未形成有效应填集合时不显示覆盖率。形成后显示“本期应填 12 / 已提交 9 / 待补资料 2 / 未处理 1”，说明去重、豁免及迟到触发口径；分母改变保留变更记录。

晨会入口生成可编辑提纲，自动带入事实和未完成事项；不预填人工结论。目标为 5 分钟内走完，不把填写全部模板作为晨会前置。

### 4.2 交易分析：一张主图、一组明细

- 经营结果：先列已可计算项目，再显示完整经营利润的缺口。分解表保持加总恒等；无法解释部分明确单列，不能塞进“其他”隐藏。
- 电量偏差：实际、预测、申报、出清、执行分开命名；电量图与经济影响图对齐时间。点击小时定位其原始时段，支持全部明细及业务列导出。
- 市场环境：电价、供需、气象、检修和约束按时间联动；资料缺口分别显示。天气芯片保留摘要入口。政策影响只在证据和适用日期确定后呈现，推断标“待核实”。
- 策略表现：策略版本、事前基准、实际采用情况、样本范围、风险与尾部表现必须一起看。样本不足允许看原始结果，但隐藏优劣结论与排名。连续亏损不直接等于策略失效，30 个相关时段不算 30 个独立样本。
- 风险检查：损失事件、险情、压力测试分区。情景调整显示约束与适用范围；不可行的储能计划不输出可实现收益。风险登记可关联交易、资料和案例。

选时段后的固定阅读顺序：发生了什么 → 金额怎么算 → 当时怎么判断 → 下一次改什么。表格保留排序、筛选、列单位和导出；不把全部说明常驻主页面。

### 4.3 结算核对：导入到归档

步骤：选择账单 → 校验公司/地区/账期及含税口径 → 预览项目匹配、重复与修订 → 确认导入 → 按项目核对 → 补凭证/更正 → 满足权限和差异规则后归档。

匹配表显示费用项目、账单金额、测算金额、差异和处理状态；点击项目展开证据和说明。零差异不等于全账正确，必须先证明核对范围完整。月度独有考核、分摊、调整保留月度归属，不按天均摊制造日度相符。

存在未解释差异时“确认归档”禁用并解释条件。有权限人员接受差异必须留授权理由、金额、证据和审计，不能由通用“忽略”按钮清空。修订账单创建新版本，旧结果可比较、不可覆盖。

### 4.4 决策回放：默认隐藏事后信息

默认当时视角，时间线显示计划留存、人工修改、申报提交、平台接收等节点；资料必须在该时刻已经收到。未出清前只显示接收，不显示成交。预测发布与首次取得时间同时约束可见范围。

当时视角的首页摘要、侧栏、图表提示、排序、标题、导出和报告入口均不能泄露事后价格、盈亏、胜败标签。正式接口也只返回允许的资料，不能先把未来数据送到浏览器再隐藏。

点击“查看事后结果”显式进入另一模式，并标明不能用这些信息评价当时决策。反事实按钮只在事后模式提供，区分“同价情景测算”“约束内可行替代”“事后上界”；结果必须携带成交假设与限制。历史资料没有留存快照时提示“只能做结果复盘，暂不能公平评价当时决策”。

人工依据、结论、责任与措施默认空白。保存草稿与本人提交分开；提交后只读，修改通过追加更正。AI 只能整理已知事实及提示遗漏，不能代填人工判断。

### 4.5 档案：让报告、案例和措施互相连接

待办关联其触发事件、模板、证据和同一份计算。报告支持日、周、月、季及定时产出/手动生成/阅读/导出，自动生成的报告保留“待人工确认”。AI 不可用时仍能生成确定性报表、填写结论和推进待办。

模板先按主体与目的选择，全部 31 类可查找；页面只显示中文业务名称，不显示模板内部编号。模板详情列就绪资料和缺口，具备哪些数据就填哪些事实，不能用一份通用表单冒充所有专业模板。

改进状态：草稿 → 待落实 → 验证中 → 已验证 / 无效撤回 / 证据不足延长。落实要执行证据；验证要原先约定的比较结果、窗口及确认人。回查到期进入待办，未完成项自动带入会议。

案例保留适用条件与反例，区分成功、失败和险情，不只收录漂亮结果；内外可见范围继承权限。会议纪要包括事实、人工结论、分工与回查。情绪与学习功能默认关闭，启用后也仅用于本人辅导，不用于排名。

## 5. 数据库字段名严禁进入用户界面

这是一条实现与验收约束，不仅是视觉文案建议。以下映射只存在于研发说明和展现层中，右列才允许进入产品。

| 技术键或状态示例（不可展示） | 用户可见措辞 |
|---|---|
| `company_id` / `region_id` / `subject_type` | 公司 / 市场地区 / 业务主体的真实业务名称 |
| `run_id` / `input_snapshot_id` | 计算记录 / 当时留存资料；需要识别时用业务日期和计算时间 |
| `sourceType: MOCK` / `self-computed` | 模拟数据 / 演示测算或系统测算 |
| `data_gap` / `endpoint-absent` | 缺少哪份资料及影响；或“本项能力尚未接入” |
| `pending` / `draft` / `submitted` | 待处理 / 草稿 / 已提交 |
| `near_miss` / `soc` | 险情（未形成损失）/ 荷电状态，并解释为剩余电量占可用容量的比例 |
| `declared_energy` / `cleared_energy` | 申报电量 / 出清电量，不得合并命名 |
| `unexplained_residual` / `rule_version` | 待解释差异 / 适用结算规则及生效日期 |

实现使用独立展现模型：接口对象 → 可校验业务模型 → 页面文案与格式化模型。模板注册表的技术键只用于绑定，名称、单位、说明由审核过的业务词典提供。未知键没有合法文案时显示“本项内容暂不能展示”，记录研发诊断；禁止以原始键兜底，也不能简单驼峰转空格后显示。

适用范围包含：标题、卡片、表单、下拉选项、图例、提示框、状态徽标、错误消息、加载提示、无障碍名称、资料说明、复制内容、打印、导出表头、报告和 AI 输出。后端异常原文不直出；用户只看到能理解的原因和下一步。复制诊断入口如有需要，仅给“问题编号”，不把 SQL、表名或原始响应放进交易员页面。

验证结合组件测试、代表性真实契约夹具和渲染后的文本检查，不能只用正则禁止下划线：真实资料标题也可能含下划线，应按内容来源和键集合识别。测试注入未登记技术键与后端报错，检查它们没有进入上述任何用户通道。

## 7. 前端实现边界与失败处理

建议 `ReviewCenterView.vue` 保留路由编排，把上下文、就绪度、计算记录、事项和选择时段收敛到页级状态。领域子页复用既有组件并逐步替换，不直接复制五套请求逻辑。

新增展现层（建议 `src/services/review/presentation/`）专门负责业务文案、单位、状态、范围和证据映射；Vue 组件不进行结算、归因或相对基准金额计算。新增客户端统一走 BFF `/api/v1/review`，既有代理按后端迁移表分期收敛，不造 Node→Python→Node 环路。

所有模块绑定同一计算记录。地区/日期/主体改变取消旧请求，并校验响应范围和请求序号；迟到旧响应不得填入新页。资料更新时提示“收到修订资料”，显式重算，整页原子切换；不把新图表与旧总额拼接。草稿关联原记录，重算后提示核对关联事实。

| 状态 | 可见内容 | 主动作 |
|---|---|---|
| 正在读取 | 骨架和当前范围；不先闪现别的公司的金额 | 必要时取消 |
| 无数据 | 具体缺口、受影响功能 | 查看补齐清单 |
| 部分可用 | 已具备条件的分项；未具备条件项说明 | 补资料；分析可用范围 |
| 读取失败 | 可理解的错误和问题编号；不伪装为空 | 重试 |
| 无权限 | 无金额/资料内容 | 管理员核实岗位权限 |
| 收到修订 | 当前完整旧版本及时间、新资料提示 | 重新计算；比较版本 |
| 写入冲突 | 保留本人草稿，告知已有新版本 | 比较差异，再追加提交 |

## 8. 设计稿验证与真实试用门槛

原型使用确定性示例：96 个 15 分钟时段，每段实际量 10、日前出清量 8、事前基准量 9 兆瓦时；日前价 300，18:00/18:15/18:30 实时价 800，其余 300 元/兆瓦时。因此日前费用 230,400、实时偏差电费 60,600、合计 291,000、基准 289,500、相对基准增益 −1,500 元。单个高价时段实际成本 4,000、基准 3,500、增益 −500 元。该模型仅用于核对交互与加总，不是任何省份完整结算规则。

月度账单为独立示例：现货 500,000、考核 10,000、分摊 2,120；测算分摊 2,000，其余相同，故差异 120 元。它不与日度示例相加，不伪装成 9 月结果。

前端投产验收必须覆盖：

1. 从总览不超过三次主动点击定位异常时段、金额来源和当时决策；不靠询问开发者理解字段。
2. 页面、提示、来源、错误、导出和 AI 输出无数据库键名或原始状态枚举；未知字段和异常注入测试通过。
3. 31 类模板逐项迁移；日/周/月/季、三主体、旧深链和晨会入口均有功能验收记录。
4. 全页数值同记录、同范围、同版本；乱序响应、切公司/地区、局部失败和修订重算测试通过。
5. 当时视角检查接口、正文、提示、导出和排序均无未来信息；历史无快照诚实降级。
6. 人工栏无自动填充；提交锁定、更正、冲突恢复、权限隔离和断网失败通过。
7. 真实交易员至少 3 人（交易、结算、负责人各有人覆盖），用脱敏历史交易和账单完成“定位异常、核对差异、回放判断、登记并回查改进”；记录任务时间、错误率和求助次数，修正后复测。3 人是可用性试用下限，不是统计效果证明。
8. 先保持原 Epic 的山西验真与新疆试用前提；各地缺少正式规则、账单或业务实绩时，验收止于对应已验证能力，不宣称全地区生产就绪。
